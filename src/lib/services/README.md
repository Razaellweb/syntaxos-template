# Service Wrappers

This directory contains **self-contained, copy-ready service wrappers** that the SyntaxOS backend agent pulls into generated products.

## Contract

Every file under `src/lib/services/<provider>.ts` is:

1. **A single TypeScript file.** No cross-file imports except the official provider SDK.
2. **A thin shim over the official provider SDK.** Does NOT reimplement HTTP, retries, or auth — the SDK handles that.
3. **Reads credentials directly from `process.env`.** No config objects, no constructor arguments.
4. **Exports both a class and a singleton.** Product code can import either:
   ```ts
   import { paystack } from "@/lib/services/paystack";
   // or
   import { PaystackService } from "@/lib/services/paystack";
   ```
5. **Normalizes common errors** (auth failure, rate-limit, not-found) into a small set of shared error classes. Other errors bubble up as-is.
6. **Wraps the full API surface** the official SDK exposes — every method the SDK offers should have a corresponding wrapper method.

## The manifest

`manifest.json` is the single source of truth for:

- Which wrappers exist
- Which npm packages must be installed alongside each wrapper
- Which environment variables each wrapper needs

The backend agent reads this manifest when:

- Copying a wrapper into a product (to know which npm deps to add)
- Collecting environment variables from the user at deploy time

**Do not edit manifest.json by hand.** The wrapper-generation pipeline owns it.

## How the agent uses a wrapper

1. Product user asks for something that needs a service (e.g. "let me charge a customer").
2. Agent reads `manifest.json`, finds the provider under the `payment` category.
3. Agent copies `src/lib/services/<provider>.ts` → `src/lib/services/<provider>.ts` in the product.
4. Agent adds the entries from `manifest.wrappers.<provider>.deps` to the product's `package.json`.
5. Agent records the entries from `manifest.wrappers.<provider>.env` so the user is prompted for them at deploy time.
6. Agent imports from `@/lib/services/<provider>` in the product's route handlers / server actions.

## Adding a new wrapper

Wrappers are generated by the SyntaxOS wrapper-generation pipeline (`backend/app/workflow/wrapper/pipeline.py`). The pipeline:

1. Loads the provider's schema from the knowledge base.
2. Fetches the provider's official SDK documentation.
3. Generates a single TypeScript file that wraps every method of the official SDK.
4. Type-checks the file against this template's `tsconfig.json`.
5. Updates `manifest.json` with the wrapper's metadata.
6. Commits and pushes to this repository.

Once pushed, every product built by the fullstack pipeline has access to the new wrapper automatically.
